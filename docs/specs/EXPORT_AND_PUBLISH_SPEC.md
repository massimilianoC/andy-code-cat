# Andy Code Cat — Export, Asset Management & Web Publishing Spec

> **Updated:** modular, layer-aware architecture. Feature A (Asset Manager) and Feature B1 (Layer 1 ZIP Export) are independent of M3 and implementable in the current MVP.
> **NGINX:** dedicated instance in the Docker cluster for full control over dynamic virtual hosts (M4b)

---

## Architectural Principles

### Double Sandbox Is Mandatory

**All** file operations (upload, download, export, delete) go through the double sandbox:

1. **User sandbox**: `jwt.sub` → authenticated `userId`.
2. **Project sandbox**: `x-project-id` header → project verified with `project.ownerUserId == jwt.sub`.

The filesystem mirrors this structure: `/data/uploads/{userId}/{projectId}/` and `/data/exports/{userId}/{projectId}/`. Paths are built exclusively from verified values — never from raw user input (path traversal prevention).

### Layer-Aware Export

| Layer | Source | Output | Status |
|---|---|---|---|
| **Layer 1** — Chat Preview | `PreviewSnapshot.artifacts` (HTML/CSS/JS) | ZIP with separate files | **MVP** |
| **Layer 2** — GenerationWorker | `dist/` from OpenCode | ZIP file tree | Future M4a v2 |

The abstraction is `ExportRecord.sourceType: 'layer1_snapshot' \| 'layer2_dist' \| ...` — extendable without breaking changes.

### Asset Manager Decoupled From Export

- **Project Asset Manager**: reference files uploaded by the user (PDF brief, brand images, markdown spec). Input for development, not output.
- **Export System**: output generated by the system (site ZIP). Uses the same storage infra but is a separate system.

## Feature A — Project Asset Manager

### A.1 Goal

Every project can have reference files uploaded by the user: PDF brief, brand images, fonts, markdown spec, code snippets. Used as context for development (passable as reference to LLM prompts) but not system output.

### A.2 Accepted File Types

| Category | MIME types | Max size |
|---|---|---|
| Images | `image/*` | 10 MB |
| Documents | `application/pdf` | 20 MB |
| Text / Code | `text/*`, `application/json` | 5 MB |

Total limit per project: **100 MB**. Max files per project: **50**.

### A.3 API Endpoints

All require `Authorization: Bearer <token>` + `x-project-id` header.

```
POST   /v1/projects/:projectId/assets
GET    /v1/projects/:projectId/assets
DELETE /v1/projects/:projectId/assets/:assetId
GET    /v1/projects/:projectId/assets/:assetId/download
```

### A.4 Entity

```typescript
interface ProjectAsset {
  id: string;              // UUID
  projectId: string;
  userId: string;
  originalName: string;    // sanitized on display
  storedFilename: string;  // {assetId}-{safeFilename} — used in the FS path
  mimeType: string;
  fileSize: number;        // bytes
  createdAt: Date;
}
```

Storage path: `/data/uploads/{userId}/{projectId}/{storedFilename}`

## Feature B — Export Layer-Aware

### B.1 ExportRecord (common abstraction)

```typescript
export type ExportSourceType = 'layer1_snapshot'; // | 'layer2_dist' in future

interface ExportRecord {
  id: string;
  projectId: string;
  userId: string;
  sourceType: ExportSourceType;
  snapshotId?: string;           // for sourceType: 'layer1_snapshot'
  status: 'pending' | 'ready' | 'failed';
  fileSize?: number;
  fileSha256?: string;
  filesIncluded: string[];
  assetPlaceholders: AssetPlaceholder[];
  downloadCount: number;
  expiresAt: Date;               // MongoDB TTL for automatic cleanup (24h)
  errorMessage?: string;
  createdAt: Date;
  readyAt?: Date;
}
```

### B.2 Download token JWT

```typescript
// payload
{
  sub: exportId,
  userId: string,
  projectId: string,
  iat: number,
  exp: number     // iat + EXPORT_DOWNLOAD_TTL (default: 3600s)
}
```

Signed with `EXPORT_JWT_SECRET` (separate from auth JWT). The download endpoint verifies only the JWT, without hitting the DB on every request.

### B.3 Download Endpoint (public — JWT only)

```
GET /v1/download/:token
```

- Verifies the JWT with `EXPORT_JWT_SECRET`
- FS path resolved from `exportId` + `userId` + `projectId` extracted from the JWT payload — **never from raw input**
- If file not found → 410 Gone (export expired/cleaned up)
- Streams the ZIP with `Content-Disposition: attachment`

```
GET /v1/exports/:exportId
```

Requires auth. Returns export status for polling.

## Feature B1 — Layer 1 ZIP Export (MVP)

### B1.1 Goal

Once satisfied with the chat preview, the user downloads a ZIP ready for deployment. **Independent of M3:** uses only `PreviewSnapshot.artifacts` already in MongoDB.

### B1.2 ZIP Structure

```
{project-slug}/
├── index.html        ← with <link> and <script src> for separate files
├── style.css         ← extracted and merged CSS
├── script.js         ← extracted and merged JS
├── assets/           ← placeholder stubs if identified
└── README.md         ← instructions + placeholder list
```

### B1.3 Artifact Post-processor

1. **Extract inline CSS** (`<style>` tag) → merge into `style.css` → replace with `<link rel="stylesheet" href="style.css">` in `<head>`
2. **Extract inline JS** (`<script>` without `src`) → merge into `script.js` → replace with `<script src="script.js"></script>` before `</body>`
3. **Merge with artifacts**: CSS/JS already separate from the artifact (already present) are prepended to the content extracted from the HTML
4. **Placeholder identifiers**: `<img src="">`, `<img src="placeholder*">`, `url('')` in CSS, `/* replace: */` comments → `assetPlaceholders[]`

### B1.4 API

```
POST /v1/projects/:projectId/export/layer1
```

**Optional body:** `{ snapshotId?: string }`

**Response 201:**

```typescript
{
  exportId: string;
  downloadToken: string;
  downloadUrl: string;       // /v1/download/{token}
  expiresAt: string;         // ISO8601
  filesIncluded: string[];
  assetPlaceholders: AssetPlaceholder[];
}
```

### B1.5 Testable Steps

```
1. POST /v1/projects/:id/export/layer1
   → 201 { exportId, downloadUrl }

2. GET {downloadUrl}
   → ZIP with index.html, style.css, script.js, README.md

3. index.html has no inline <style>, has <link href="style.css">
   has no inline <script>, has <script src="script.js">

4. Expired token → 401

5. ExportRecord in MongoDB: status 'ready', fileSha256 present

6. GET /v1/exports/:exportId → { status: 'ready', downloadCount: 1 }
```

## 1. Feature 1 — ZIP Export

### 1.1 Goal

Once satisfied with the generated preview, the user can download a complete ZIP package ready for manual deployment on any server. No dependency on Andy Code Cat after the download.

### 1.2 ZIP Package Structure

```
{project-slug}/
├── index.html
├── style.css
├── script.js
├── assets/
│   ├── placeholder-hero.jpg    ← mock image (to replace)
│   ├── placeholder-about.jpg   ← mock image
│   └── logo.svg                ← mock icon/SVG
└── README.md
```

**Dynamically generated README.md** — contains:

- Project name and export date
- Deploy instructions (open index.html directly or on NGINX/Apache)
- List of assets to replace with path, recommended dimensions and context of use
- Link to the Andy Code Cat documentation

**File conventions:**

- CSS and JS are always separate files (not inline in the HTML), even if the LLM produced them inline: the post-processor extracts them.
- Placeholder assets have semantic names (`placeholder-{section}.{ext}`) to help the user understand what to replace.

### 1.3 API Endpoint

```
POST /v1/projects/:id/export/zip
```

**Body (optional):**

```typescript
{
  snapshotId?: string;   // if omitted, uses the latest available snapshot
}
```

**Response (202 Accepted):**

```typescript
{
  exportId: string;
  downloadToken: string;    // signed JWT, TTL 1h
  downloadUrl: string;      // /v1/download/:token
  expiresAt: string;        // ISO8601
}
```

**Download endpoint:**

```
GET /v1/download/:token
```

Verifies the JWT, streams the ZIP file with `Content-Disposition: attachment`. Once downloaded, the token is not invalidated (it can be downloaded multiple times until it expires). The file on the filesystem is cleaned up after 24h via a cleanup job.

### 1.4 ZIP Generation Logic

```typescript
// apps/api/src/application/use-cases/ExportProjectZip.ts
class ExportProjectZip {
  async execute(projectId, snapshotId?, userId): Promise<ExportRecord> {
    // 1. Fetch snapshot (or the latest from the conversation)
    // 2. Extract HTML/CSS/JS from the artifacts
    // 3. Post-processing:
    //    - Split inline CSS/JS into dedicated files if necessary
    //    - Update <link> and <script> in the HTML
    //    - Identify placeholder assets (empty src, placeholder URLs, mock data)
    // 4. Generate README.md with the asset list
    // 5. Create ZIP at /data/exports/{exportId}.zip
    // 6. Compute fileSize and SHA-256 checksum
    // 7. Generate signed JWT for download
    // 8. Save ExportRecord in MongoDB
    // 9. Return ExportRecord
  }
}
```

**Post-processor — CSS/JS separation:**

- Looks for `<style>` tags in the HTML → extracts into `style.css` + adds `<link rel="stylesheet" href="style.css">`
- Looks for inline `<script>` tags in the HTML → extracts into `script.js` + adds `<script src="script.js"></script>`
- CSS `@import` directives are left intact

**Post-processor — asset identification:**

- Looks for `<img src="">` with empty or placeholder-like src
- Looks for `url('')` in CSS with empty or placeholder values
- Looks for `/* replace: ... */` comments inserted by the LLM
- Generates a list in README.md with: path in the HTML/CSS, recommended dimensions, context (e.g. "hero image, about section")

### 1.5 Export as Synchronous vs Asynchronous Generation

For MVP: **synchronous** (wait time < 2s for typical projects).
If `dist/` exceeds 10MB → responds 202 with `status: "pending"` and a BullMQ job queue.
The user polls `GET /v1/exports/:exportId` until `status: "ready"`.

### 1.6 Signed JWT for Download

```typescript
// payload
{
  sub: exportId,
  userId: string,
  projectId: string,
  iat: number,
  exp: number    // +3600s (1h)
}
```

Signed with `EXPORT_JWT_SECRET` (separate from the auth JWT). Verified in the download endpoint middleware without hitting the DB.

## 2. Feature 2 — Web Publishing with NGINX

### 2.1 Two Publishing Modes

| Mode | Subdomain | TTL | Availability | Use case |
|---|---|---|---|---|
| **Random** | `{adjective}-{noun}-{N}.Andy Code Cat.io` | 24h | Always available | Quick sharing, temporary demo |
| **Reserved** | `{chosen-name}.Andy Code Cat.io` | None | If not already taken | Persistent site, branded sharing |

### 2.2 Random Subdomain (Feature 2a — first MVP priority)

**User flow:**

1. User clicks "Publish temporary preview"
2. System generates a unique random subdomain (wordlist + number)
3. Copies `dist/` to `/var/www/Andy Code Cat/{subdomain}/`
4. Writes `nginx.conf` for the virtual host
5. Runs `nginx -s reload`
6. Shows the user the URL: `https://velvet-fox-42.Andy Code Cat.io`
7. Below the URL: a "Expires in 24h" badge with countdown

**TTL and cleanup:**

- MongoDB TTL index on `SubdomainAllocation.expiresAt` (24h)
- BullMQ job scheduled hourly: looks for expired allocations, removes the NGINX conf, deletes `dist/` from the filesystem, runs `nginx -s reload`
- Alternative: session TTL (user disconnects → expires at logout + 30min grace). For MVP, a **fixed 24h** is used — simpler.

**Subdomain generation:**

```typescript
// 200 adjectives × 200 nouns × 100 numbers = 4,000,000 possible combinations
const subdomain = `${pickRandom(adjectives)}-${pickRandom(nouns)}-${randomInt(10,99)}`;
// Verifies uniqueness in SubdomainAllocations (status: active)
// Max 3 retries on collision, then a 503 error
```

### 2.3 Reserved Subdomain (Feature 2b — second priority)

**User flow:**

1. User clicks "Reserve dedicated subdomain"
2. Input field: `[_____________].Andy Code Cat.io`
3. Real-time validation (300ms debounce): `GET /v1/subdomains/check?name=mysite`
   - Response: `{ available: true }` or `{ available: false, reason: "already_taken" }`
4. Confirmation → system reserves and deploys
5. Permanent URL until explicit deletion

**Reserved subdomain rules:**

- 3-30 characters
- Only `[a-z0-9-]`, cannot start or end with `-`
- Blacklist: `www`, `api`, `admin`, `mail`, `Andy Code Cat`, `app`, `cdn`, ...
- A user can have max 3 reserved subdomains on the Free plan, unlimited on Pro

**Reservation:**

- The reservation happens at the time of the first deploy, not before (no "booking" without a deploy)
- If the deploy fails, the reservation is released automatically
- To update an existing reserved subdomain: re-deploy overwrites `dist/` and reloads nginx

### 2.4 Web Publishing API Endpoints

```
POST /v1/projects/:id/publish
```

**Body:**

```typescript
{
  type: 'random' | 'reserved';
  subdomain?: string;    // only for type: 'reserved'
  visibility: 'public' | 'password' | 'private';
  password?: string;     // only if visibility: 'password'
  snapshotId?: string;   // if omitted, uses the latest snapshot
}
```

**Response (202 Accepted):**

```typescript
{
  deploymentId: string;
  status: 'deploying';
  url: string;           // https://{subdomain}.Andy Code Cat.io
  subdomain: string;
  expiresAt?: string;    // only for type: 'random'
}
```

```
GET /v1/projects/:id/deployments           // list the project's deployments
GET /v1/deployments/:deploymentId          // single deployment status
DELETE /v1/deployments/:deploymentId       // remove deployment + nginx cleanup
GET /v1/subdomains/check?name=mysite       // check availability
```

### 2.5 Internal Deploy Flow

```typescript
// apps/api/src/application/use-cases/PublishProject.ts
class PublishProject {
  async execute(input): Promise<SiteDeployment> {
    // 1. Verify that dist/ exists for the project/snapshot
    // 2. Allocate subdomain (random or reserved):
    //    - random: generate, verify uniqueness, insert SubdomainAllocation
    //    - reserved: verify availability, insert SubdomainAllocation
    // 3. Create SiteDeployment with status: 'deploying'
    // 4. Enqueue BullMQ job: DeployWorker
    // 5. Return SiteDeployment (client polls or uses SSE)
  }
}

// Worker: apps/api/src/infrastructure/workers/DeployWorker.ts
class DeployWorker {
  async process(job): Promise<void> {
    // 1. Copy dist/ → /var/www/Andy Code Cat/{subdomain}/
    // 2. Generate nginx.conf from the Nunjucks template
    // 3. Write to /etc/nginx/sites-enabled/{subdomain}.conf
    // 4. nginx -t (syntax check) → rollback if it fails
    // 5. nginx -s reload
    // 6. Update SiteDeployment: status: 'live', deployedAt
    // 7. If random: set expiresAt = now + 24h on SubdomainAllocation
  }
}
```

### 2.6 nginx.conf Template for Virtual Host

```nginx
# Nunjucks template: nginx-templates/vhost.conf.njk
server {
    listen 80;
    server_name {{ subdomain }}.Andy Code Cat.io;

    root /var/www/Andy Code Cat/{{ subdomain }};
    index index.html;

    {% if visibility == 'password' %}
    auth_request /_pf_auth;
    auth_request_set $auth_status $upstream_status;

    location = /_pf_auth {
        internal;
        proxy_pass http://api:4000/_pf_auth/{{ subdomain }};
        proxy_pass_request_body off;
        proxy_set_header Content-Length "";
    }
    {% endif %}

    location / {
        try_files $uri $uri/ /index.html;
    }

    # Cache static assets
    location ~* \.(css|js|jpg|png|svg|woff2)$ {
        expires 7d;
        add_header Cache-Control "public, immutable";
    }

    # Baseline security
    add_header X-Frame-Options "SAMEORIGIN";
    add_header X-Content-Type-Options "nosniff";

    {% if expiresAt %}
    # Random subdomain — expires {{ expiresAt }}
    add_header X-Andy Code Cat-Expires "{{ expiresAt }}";
    {% endif %}
}
```

In production (SSL): the template extends with an HTTPS block and a 80→443 redirect.
The wildcard cert `*.Andy Code Cat.io` is managed separately (one-time, not per virtual host).

## 3. MongoDB Schemas

### 3.1 `exports` — ZIP export history

```typescript
interface ExportRecord {
  _id: ObjectId;
  projectId: ObjectId;
  userId: ObjectId;
  snapshotId?: ObjectId;       // which snapshot was exported

  status: 'pending' | 'ready' | 'failed' | 'expired';

  // File metadata (not the file itself — cleaned up after TTL)
  fileSize?: number;           // bytes
  fileSha256?: string;         // checksum for integrity
  filesIncluded: string[];     // ['index.html', 'style.css', ...]
  assetPlaceholders: Array<{
    path: string;              // 'assets/placeholder-hero.jpg'
    usedIn: string;            // 'index.html <img> hero section'
    recommendedSize?: string;  // '1920x600px'
  }>;

  // Download
  downloadToken?: string;      // JWT (hashed in DB for audit, not the raw version)
  downloadTokenExpiresAt?: Date;
  downloadCount: number;       // how many times downloaded

  createdAt: Date;
  expiresAt: Date;             // filesystem cleanup after this timestamp
}

// Indexes
db.exports.createIndex({ projectId: 1, createdAt: -1 });
db.exports.createIndex({ userId: 1 });
db.exports.createIndex({ expiresAt: 1 }, { expireAfterSeconds: 0 }); // MongoDB TTL index
```

### 3.2 `subdomain_allocations` — subdomain management

```typescript
interface SubdomainAllocation {
  _id: ObjectId;
  subdomain: string;           // 'velvet-fox-42' or 'my-brand'
  type: 'random' | 'reserved';

  // Ownership
  userId: ObjectId;            // who published it
  projectId: ObjectId;         // linked project

  // State
  status: 'active' | 'expired' | 'released';

  // TTL (random only)
  expiresAt?: Date;            // null for reserved

  // Audit
  deploymentId: ObjectId;      // ref to SiteDeployment
  createdAt: Date;
  updatedAt: Date;
}

// Indexes
db.subdomain_allocations.createIndex({ subdomain: 1 }, { unique: true, sparse: false });
// Uniqueness is global: even if expired, the subdomain is still in the document
// but status: 'expired' allows re-allocation (check: subdomain + status: 'active')
db.subdomain_allocations.createIndex({ subdomain: 1, status: 1 });
db.subdomain_allocations.createIndex({ userId: 1, type: 1 });
db.subdomain_allocations.createIndex({ projectId: 1 });
db.subdomain_allocations.createIndex({ expiresAt: 1 }, { expireAfterSeconds: 0 }); // auto-expire random
```

**Note on uniqueness:** MongoDB's TTL index removes the document once `expiresAt` passes (for `random` only). The subdomain then becomes re-allocatable. `reserved` subdomains have no `expiresAt` and are removed only via explicit deletion.

### 3.3 `site_deployments` — live deployment registry

```typescript
interface SiteDeployment {
  _id: ObjectId;
  projectId: ObjectId;
  userId: ObjectId;
  snapshotId?: ObjectId;

  // Address
  subdomain: string;
  url: string;                 // 'https://velvet-fox-42.Andy Code Cat.io'
  type: 'random' | 'reserved' | 'custom_domain';

  // State
  status: 'deploying' | 'live' | 'failed' | 'expired' | 'taken_down';
  errorMessage?: string;       // if status: 'failed'

  // nginx configuration
  nginxConfPath: string;       // '/etc/nginx/sites-enabled/velvet-fox-42.conf'
  nginxConfChecksum?: string;  // SHA-256 of the conf for drift detection

  // SSL
  sslEnabled: boolean;
  sslCertPath?: string;
  sslExpiresAt?: Date;

  // Visibility
  visibility: 'public' | 'password' | 'private';
  passwordHash?: string;       // bcrypt, only if visibility: 'password'

  // Statistics
  deployedAt?: Date;
  lastAccessedAt?: Date;       // updated from nginx access log (Phase 2)
  allocationId: ObjectId;      // ref to SubdomainAllocation

  createdAt: Date;
  updatedAt: Date;
}

// Indexes
db.site_deployments.createIndex({ projectId: 1, status: 1 });
db.site_deployments.createIndex({ subdomain: 1, status: 1 });
db.site_deployments.createIndex({ userId: 1, createdAt: -1 });
db.site_deployments.createIndex({ allocationId: 1 });
```

## 4. NGINX in the Docker Cluster

### 4.1 Motivation

Adding nginx to `docker-compose.yml` enables:

- **Full control** over dynamic virtual hosts without depending on the host's nginx
- **Hot reload** via `docker exec Andy Code Cat-nginx nginx -s reload` (no restart, no downtime)
- **Shared volume** with the API for direct writes to conf files and `dist/`
- **Full isolation** in dev/staging — same configuration across environments

### 4.2 nginx Service in docker-compose

```yaml
nginx:
  image: nginx:1.25-alpine
  container_name: Andy Code Cat-nginx
  restart: unless-stopped
  ports:
    - "80:80"
    - "443:443"
  volumes:
    - ./nginx/nginx.conf:/etc/nginx/nginx.conf:ro        # main conf
    - ./nginx/sites-enabled:/etc/nginx/sites-enabled     # virtual hosts (written by the API)
    - ./data/www:/var/www/Andy Code Cat                      # deployed dist/
    - ./data/certs:/etc/letsencrypt:ro                   # SSL certificates
  depends_on:
    - api
  networks:
    - Andy Code Cat-net
```

**Directory layout on host:**

```
nginx/
├── nginx.conf          ← main conf (includes sites-enabled/*)
└── sites-enabled/      ← empty directory, populated dynamically by the API
data/
├── www/
│   ├── velvet-fox-42/  ← deployed dist/
│   └── my-brand/
└── certs/              ← wildcard cert *.Andy Code Cat.io
```

**Main nginx.conf:**

```nginx
worker_processes auto;
events { worker_connections 1024; }

http {
    include       /etc/nginx/mime.types;
    default_type  application/octet-stream;
    sendfile      on;
    keepalive_timeout 65;
    gzip on;
    gzip_types text/css application/javascript image/svg+xml;

    # Include all dynamic virtual hosts
    include /etc/nginx/sites-enabled/*.conf;

    # Fallback: 404 for unconfigured subdomains
    server {
        listen 80 default_server;
        return 404;
    }
}
```

### 4.3 API → nginx Communication

The API has no direct access to the nginx process. Reload happens via the **Docker socket** or a small script:

**Option A (Docker socket — recommended for MVP):**
The API calls `docker exec Andy Code Cat-nginx nginx -s reload` via the Node.js Docker SDK:

```typescript
// apps/api/src/infrastructure/nginx/NginxController.ts
import Docker from 'dockerode';

export class NginxController {
  private docker = new Docker({ socketPath: '/var/run/docker.sock' });

  async reload(): Promise<void> {
    const container = this.docker.getContainer('Andy Code Cat-nginx');
    await container.exec({
      Cmd: ['nginx', '-s', 'reload'],
      AttachStdout: true,
      AttachStderr: true,
    }).then(exec => exec.start({}));
  }

  async test(confPath: string): Promise<boolean> {
    // nginx -t before reload, to catch syntax errors
  }
}
```

```yaml
# In the api service of the docker-compose:
volumes:
  - /var/run/docker.sock:/var/run/docker.sock  # mount socket
```

**Option B (nginx-proxy sidecar):** more secure for production (Phase 2).

### 4.4 Automatic Cleanup of Expired Subdomains

```typescript
// BullMQ job scheduled hourly
// apps/api/src/infrastructure/workers/SubdomainCleanupWorker.ts

async function cleanupExpiredSubdomains() {
  const expired = await SubdomainAllocationModel.find({
    type: 'random',
    status: 'active',
    expiresAt: { $lte: new Date() }
  });

  for (const allocation of expired) {
    // 1. Remove the nginx conf file
    await fs.unlink(`/nginx/sites-enabled/${allocation.subdomain}.conf`);
    // 2. Remove dist/
    await fs.rm(`/data/www/${allocation.subdomain}`, { recursive: true });
    // 3. Update SiteDeployment status: 'expired'
    // 4. Update SubdomainAllocation status: 'expired'
  }

  if (expired.length > 0) {
    await nginxController.reload();
  }
}
```
